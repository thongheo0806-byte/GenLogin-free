## Efficiency/architecture changes

- Metadata import now validates all rows up front and writes within one SQLite transaction, preserving atomicity and reducing commit overhead; the claimed `~100×` acceleration has **not** been remeasured here.
- Search input is debounced at 200 ms and filters a cached profile catalog; status events update the affected row instead of re-querying all rows.
- SQLite connection remains short lived per operation (safer with concurrent desktop, browser and API threads), now with WAL setup, FK enforcement and `PRAGMA user_version=1`. Long-lived connection pooling and full schema migrations are deliberately deferred.
- `ExtensionLibrary._get` now queries by ID instead of scanning the entire package catalog.
- Profile editor credential handling moved to a service with compensating rollback.
- Remaining: full action registry/unified dispatcher, large UI decomposition, real Windows browser lifecycle/manual close test, proxy integration and disk-full tests, Windows UI tab interaction, OS vault integration, library error recovery, release parity gates.
